## P2 — Online authenticated app + persistence (complete)

Slice 1 (commit `776f941`, branch `v3`): **domain + storage foundation**.

- `packages/domain`: the content editorial and per-channel publication state
  machines as explicit transition tables (`submitting -> buffer_sent` is
  structurally impossible — remote facts require remote readback);
  the approval proof (canonical JSON → SHA-256; source ids are a set, asset
  hashes a sequence; per-channel binding); and the policy schema with
  blueprint 10.4 defaults where `publishing_enabled` and `autonomy_enabled`
  are hard `false`.
- `packages/storage`: SQLite via the Node built-in `node:sqlite` driver —
  **zero native dependencies** (DatabaseSync verified on Node 24.21, SQLite
  3.53.4). `openDatabase()` enforces foreign keys, a 5 s busy timeout and WAL
  on file databases; `applyMigrations()` is a forward-only transactional
  runner; `migrations/0001_init.sql` implements the full blueprint-section-9
  contract (24 tables with CHECK-constrained states and UNIQUE
  identity/idempotency keys).
- Repositories: users; sessions (opaque token, only its SHA-256 stored,
  expiry + revocation + last-seen); studio projects (**immutable revisions**
  with `revision_sha` and `OptimisticConcurrencyError` on stale writers);
  audit events (append-only); policy settings (validated overrides over the
  safe defaults).

**Evidence (executed):** 30 new unit assertions written RED→GREEN; combined
mutation check failed exactly the three aimed tests (sabotaged
`submitting -> buffer_sent` edge, removed canonical key sorting, skipped the
optimistic lock), all reverted; full `npm run verify` green — smoke
`[40, 16, 14336]`, **100 unit assertions**, typecheck OK, 28/28 Playwright,
standalone sha256 `d7501b4d…` byte-identical.

Slice 2 (commit `f2acea3`, branch `v3`): **authenticated web skeleton** —
`apps/web` (Express 5, bundled with esbuild).

- Hardened admin bootstrap: an empty user table without
  `RG_ADMIN_USERNAME`/`RG_ADMIN_PASSWORD` refuses to start; existing users
  are never reset by a restarting container. scrypt password hashes
  (self-describing `scrypt$N$r$p$salt$hash`, constant-time verify).
- Sessions: migration `0002_sessions_csrf.sql` adds a session-bound
  `csrf_token` (NOT NULL); cookies are `HttpOnly`, `SameSite=Strict`,
  `Secure` forced in production; mutating routes require `x-csrf-token`
  matched constant-time against the session row, so cross-session tokens
  are rejected. Login is rate-limited (5 failures / 15 min per
  client+username, sliding window, success resets); disabled accounts and
  expired/revoked sessions are rejected; unknown usernames still pay
  scrypt against a throwaway hash (uniform 401 body, no user enumeration).
- `/health/live` (no dependencies) and `/health/ready` (real
  `schema_migrations` state; degrades to 503 when the database is gone);
  uniform `{error:{code,message}}` JSON, 64 kb body cap (413/400 codes),
  `nosniff`/`DENY`/`no-referrer`/CSP headers, `x-powered-by` off. Auth
  actions append audit events (no passwords or tokens).

**Evidence (executed):** 22 new RED→GREEN assertions — config boundaries,
scrypt hashing, sliding-window limiter, and a 10-case real-HTTP integration
suite over ephemeral ports (bootstrap, full login/me/logout lifecycle with
cookie attributes, CSRF cross-session rejection, rate-limit
lock/unlock/reset, restart persistence with a surviving session, uniform
errors, readiness degradation); combined mutation run (5 sabotages: CSRF

Slice 3 (commit `3f89959`, branch `v3`): **projects/revisions API + the
online studio editor** (blueprint lines 798–803).

- API `/api/v1/projects` (session + `x-csrf-token` on writes): create, list
  (strict pagination), fetch, append-only revision saves with
  `expectedRevision` optimistic control — a stale writer receives 409
  `revision_conflict` carrying `currentRevision` — revision history, single
  revision fetch, and `attachment` export. Content goes through the shared
  `restoreProject()` pipeline (v1 imports migrate up; invalid layouts are
  400s with no partial writes) and is re-stamped with the v2 `format`/
  `version` markers for storage. Row `name` is a denormalized copy synced on
  save; writes append audit events (`project.create`,
  `project.revision_saved`).
- App shell: `/` → `/studio/`; `/login` (bounces authed visitors);
  `/studio/` gated server-side, `/studio` canonicalized. **Regression note:**
  Express 5 pattern matching makes `/studio` match `/studio/` too, so the
  initial two-route redirect pair looped forever; a single array-pattern
  handler now serves both (pinned by an integration assertion). `/assets`
  serves Design Kit files plus the built `studio-core.js`; CSP gains
  `img-src 'self' data:` for the embedded logos (scripts/styles remain
  `'self'`-only).
- Online editor UI (`apps/web/static`, shared v2 design tokens, strict CSP —
  external JS/CSS only, no inline styles): sign-in, project list, cover
  editor, explicit revision saves, immutable history with
  restore-as-new-revision, export download, stale-writer conflict banner
  with reload reconciliation. The browser stores nothing online
  (`localStorage.length === 0` in the journey test); the server owns state.
